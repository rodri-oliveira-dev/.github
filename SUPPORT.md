# Support

This file defines the default support guidance for repositories maintained under the `rodri-oliveira-dev` account. Repository-specific support documentation, when present, takes precedence.

## English

### Where to ask for help

Use the repository's issue tracker when you have:

- a reproducible bug;
- a feature request or improvement proposal;
- a documentation problem;
- a question that is directly related to the repository and whose answer would benefit other users.

Before opening an issue, check the README, existing documentation, open and closed issues, and any repository-specific contribution guidance.

Use the provided bug or feature issue form when available. Include the smallest useful reproduction, relevant versions/environment, expected behavior, actual behavior, and logs or screenshots that do not contain secrets.

### What support does not cover

Open-source maintenance does not imply a response-time, support-level, consulting, or compatibility guarantee unless a repository explicitly documents one.

General programming questions, unrelated environment troubleshooting, commercial support, and requests that do not concern the repository may be redirected or closed.

### Security is different from support

**Do not report suspected vulnerabilities, leaked credentials, or exploit details in a public issue.** Use the repository's **Security** tab and its Security policy. When Private Vulnerability Reporting is available, use **Security → Report a vulnerability**.

If you are unsure whether something is a normal bug or a security issue, prefer the private security-reporting path when disclosure could expose credentials, private data, authorization bypasses, or an exploitable weakness.

## Português

Este arquivo define a orientação padrão de suporte para os repositórios mantidos na conta `rodri-oliveira-dev`. Quando um repositório possuir documentação de suporte própria, ela tem prioridade.

### Onde pedir ajuda

Utilize o rastreador de issues do repositório quando houver:

- um bug reproduzível;
- uma solicitação de funcionalidade ou proposta de melhoria;
- um problema de documentação;
- uma dúvida diretamente relacionada ao repositório cuja resposta possa ajudar outras pessoas.

Antes de abrir uma issue, consulte o README, a documentação existente, issues abertas e encerradas e eventuais orientações específicas de contribuição.

Quando disponíveis, utilize os formulários de bug ou funcionalidade. Inclua a menor reprodução útil, versões/ambiente relevantes, comportamento esperado, comportamento observado e logs ou screenshots que não contenham secrets.

### O que o suporte não cobre

A manutenção de um projeto open source não implica prazo de resposta, nível de suporte, consultoria ou garantia de compatibilidade, exceto quando o próprio repositório documentar explicitamente essas condições.

Dúvidas gerais de programação, troubleshooting de ambiente sem relação com o projeto, suporte comercial e solicitações fora do escopo do repositório podem ser redirecionadas ou encerradas.

### Segurança é diferente de suporte

**Não reporte vulnerabilidades suspeitas, credenciais vazadas ou detalhes de exploração em uma issue pública.** Utilize a aba **Security** do repositório e sua política de segurança. Quando o Private Vulnerability Reporting estiver disponível, use **Security → Report a vulnerability**.

Se houver dúvida entre bug comum e problema de segurança, prefira o canal privado de segurança quando a divulgação puder expor credenciais, dados privados, bypass de autorização ou uma falha explorável.
